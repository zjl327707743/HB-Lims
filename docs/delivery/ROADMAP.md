# 实施路线

当前栈已收敛，按 [TECH-V1](../standards/README.md) 开发；不再并行实现Vue/Django等历史候选。质量规则、存储和精确版本仍是门禁。

| 阶段 | 任务 | 退出条件 |
| --- | --- | --- |
| M0 | #2需求、#3治理、#8工程准入、#9验证策划 | URS差异/风险清楚，技术依赖/存储门禁有负责人，实际权限保护落实 |
| M1 | #4 Next/AntD前端；与API合同/权限审计底座并行 | V3.1外观保留、合成Mock及真实浏览器证据，不把Mock视为正式业务 |
| M2 | #5 FastAPI/PG纵向业务闭环 | 请验至报告归档含授权、签名、异常、事务/审计和拒绝路径 |
| M3 | #6 资源/留样/稳定性/EM | 各域共享底座，小PR组合回归 |
| M4 | #7 接口/性能/恢复与受控试点 | 固定制品、第三方按协议验证、偏差关闭和QA批准 |

第一条完整链：请验→取样/合法跳过→接收分样→资质分配→结果/受控计算→独立复核→异常处置→批准→报告归档/打印。不要只做样品/结果CRUD后才补审计与权限。

前端与后端在合同稳定后并行，QA/验证方提前审阅可测试性；生产数据迁移、设备接入及发布另行批准。详情见 [VAL-V1](../standards/DELIVERY_VALIDATION.md)。
