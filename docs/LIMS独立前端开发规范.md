# 海滨 LIMS 独立前端开发规范

2026-11-16 · 适用于 HB-Lims 独立开发

## 开发依据

- 业务需求以[六车间 QC 实验室信息管理系统用户需求说明](六车间QC实验室信息管理系统用户需求说明.docx)原件为准。实施时按 URS 原编号记录页面、业务动作、实现状态和验收用例。
- 界面与交互以 [V3.1 已验收 HTML 包](../LIMS_V3.1_已采用交付包.zip)为准。解压后用浏览器打开 `海滨LIMS.html`。HTML 的 SHA-256 为 `8571548ef60bfa9d5d54508beea4b7713787929d7fa22601b368cf4f15860515`。
- 在本仓库独立开发 LIMS。首阶段用本地测试数据走通业务，前端独立运行。接口适配、真实身份、设备联接和正式验收在具备相应条件后实施。

## 界面与操作

- 沿用 V3.1 的悬浮玻璃顶栏、圆角侧栏、紫色主操作和导航选中态。顶栏保留海滨与健康元原标识、“海滨实验室”及“HBOS / LIMS”。侧栏标题为“LIMS / 实验室质量管理”。
- “我的工作”组织今日工作、我的检验和复核与批准。“今日工作”保留“开始我的工作”。新建请验从“请验管理”进入。
- 检验报告采用验收版的双品牌页眉、居中报告标题、结果与判定表、电子签名卡。报告预览与打印共用正文，保留标准版本、结果来源及签署记录。打印记录须关联报告、用途、次数和操作人。
- 仪器总览按设备类型显示图标和可用状态。环境监测支持按厂房图纸配置和查看点位。取样、留样、稳定性、试剂等标签从业务记录生成，可预览和打印。扫码枪与打印设备用图标表示接入状态。
- 自定义单选适用统一的触发器、选项列表和选择状态。支持键盘方向键、确认、取消和焦点恢复。表单应显示字段名称、必填和出错原因。台账、抽屉、弹窗在窄屏上仍可操作。

## 核心业务

| 业务域 | 首阶段可验收的行为 |
| --- | --- |
| 请验与取样 | 请验支持草稿及提交。取样计划保留规则版本、取样人、件数、数量、位置及时间。签署取样后可生成标签并进入接收。 |
| 接收与分配 | 核对样品、包装、数量和交接信息。接收后按实验室、检验组和具备相应资格的人员分配，待办与台账同步。 |
| 检验与电子记录 | 关联方法、SOP、标准版本、仪器和试剂。记录原始值、公式参数、计算值、修约及判定。受控修改填写原因并保留历史。 |
| 复核与放行 | 人员按职责领取待办并独立签署。复核可退回，原提交人按业务规则撤回。异常保留原始结果及复测关系，未处置时阻断放行。最终批准后归档报告。 |
| 稳定性与留样 | 稳定性保留条件、时间点、数量及交接签收。留样保留登记、位置、观察、领用、销毁及流水。样品均支持标签。 |
| 设备与用品 | 管理台账、附件、预约、自检、校准和维护。用品通过流水体现领还，过期或库存不足时阻断，管制物料由两名不同人员确认。菌种可查看父子记录及传代链。 |
| 环境监测 | 从厂房点位、区域状态和周期生成计划。按计划管理采样、培养、计数、温湿度及趋势，并关联检验记录。 |
| 配置与追溯 | 支持标准、模板、角色范围、人员资质、规则、流程、查询统计、审计和备份。真实外设及系统接口接入后按实际连接状态展示回执。 |

## 工程实现

1. 按业务域拆分页面、组件和状态。将样品、请验、标准快照、签名、库存流水及审批状态作为各自可追溯的记录，列表、详情与待办引用同一记录。
2. 分离页面、业务命令和数据适配。所有状态流转由动作统一校验角色、当前状态、必填项及前置条件。先提供本地适配，真实服务接入时复用页面合同。
3. 本地适配使用可重置的测试数据和带版本的浏览器存储。刷新应保留当前业务进度。签署绑定对象、角色、时间和签署含义。审计记录关联操作对象、前后值及原因。
4. 把默认、空数据、加载、输入错误、权限不足、冲突和操作结果写入页面验收表。正式身份与数据范围、签名认证、审计保存、并发及恢复由后端和目标环境验证。
5. 采用已验收的文案、图标和组件布局。前端业务导航不加入开发方案、需求覆盖矩阵或知识转移等交付材料。

## 验收

- 在桌面和窄屏核对顶栏、侧栏、我的工作、报告及标签，验证检验报告预览与打印一致。
- 从请验到报告归档逐步核对状态、责任人、六次签署、电子记录和打印记录。验证错误密码、环节越序、非指定人操作、异常阻断和刷新恢复。
- 验证取样数量及标签、稳定性交接数量、点位图和监测流程、留样观察及出入库、仪器状态、过期领用拦截、管制物料双人确认及传代链。
- 每条 URS 写明设计入口、验收步骤、结果及所需外部条件。验收保留浏览器、版本、测试身份和失败证据。真实系统接口、设备、安全及数据完整性按各自验收条件核实。
