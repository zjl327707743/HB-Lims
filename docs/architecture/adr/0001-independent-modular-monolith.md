# ADR-0001 独立开发、合同先行、模块化单体

**后续评审提示（2026-11-16）：** 本页为第一版提案。Owner后来明确要求独立LIMS及第三方验证，并要求并列比较FastAPI、MySQL、Java、.NET与多种前端。请以 [ADR-0002独立验证与多技术路线评估](0002-independent-validation-architecture-evaluation.md) 为后续待决策方案；两份都未获正式批准，不得把本页Django/PostgreSQL建议视为冻结选型。

状态：**Proposed — 待Owner及技术负责人批准**。日期2026-11-16。

## 背景

现有规范要求独立前端、合成数据先行并保持V3.1。需求包含强状态约束、标准版本、计算、签名审计及多系统接口。用户预估几百名使用人员，实际并发、团队能力和现场基础设施尚未确认。人数本身不足以支持微服务决策。

## 推荐主路径

| 层 | 建议 | 取舍 |
| --- | --- | --- |
| 前端 | Vue3 + TypeScript + Ant Design Vue；Vite/Router/状态管理选兼容稳定版本 | 保留已采用视觉，按业务域拆分；先Mock适配、后HTTP适配 |
| 后端 | Django 5.2 LTS + Django REST framework，模块化单体 | 使用明确业务命令与事务；框架并不自带制药签名/审计合规能力 |
| 数据 | PostgreSQL 17受支持补丁版起步；18可经兼容验证再定 | 事务、约束、迁移和查询；生产不能用浏览器存储或SQLite替代 |
| 文件 | 与业务数据库分离的对象/文件存储，元数据和来源在DB | 原始文件、报告、模板分区；选择实际可维护且许可清晰的产品 |
| 异步 | 需要时增加worker处理报表、导入、通知、接口重试 | 同一代码库部署独立进程；队列产品待吞吐/运维评估，不先堆中间件 |
| 测试 | 前端单测与浏览器E2E；Python测试和真实PG集成；安全/恢复/性能专项 | 工具通过不等于QC/QA业务验收 |
| 部署 | 开发Docker Compose；测试与生产隔离，TLS反向代理、受控备份 | 生产编排/高可用取决于IT约束，不默认Kubernetes |

Django官方当前给5.2 LTS的扩展支持至2028年4月；PostgreSQL官方给17系列支持至2029年11月。选择受支持系列并锁定当时通过验证的补丁/依赖/镜像摘要，不追逐预览版。当前不生成未经确认的应用锁文件。

## 备选与不选

若实际核心后端团队主要使用Java，则改选Spring Boot模块化单体，通过另一ADR确认；不要同时维护Python和Java两个同职责业务后端。若已有合格商业产品能覆盖关键差距，也应以同一URS/PoC和总拥有成本比较，而非预设自研必然更便宜。

不默认回到HBOS的Frappe代码库，不直接移植旧LIMS或共享业务数据库；需要复用时逐模块审查后通过接口集成。初期不采用微服务、Kafka、Kubernetes或独立搜索集群作为默认前置条件，除非实际隔离、吞吐或运维证据支持。

## 核心实现约束

- 页面→业务命令→数据适配；权限与状态的最终裁决在服务端。
- 样品、标准/方法/公式/模板/流程均有稳定标识和版本；历史执行绑定快照。支持批准后配置流程，不把审批层级硬编码。
- 结果修订、签名、审计和Outbox同事务提交；乐观版本与幂等键防止重复动作。附件上传先暂存和校验，事务确认引用；失败清理，不假装对象存储参与DB事务。
- Decimal数值、单位和明确修约规则；公式白名单解析，不用eval。前端计算仅预览，批准结果由受控计算规则确认。
- 身份与角色再叠加厂区/实验室/小组/任务范围和资质；列表、详情、导出、搜索和附件统一过滤。管理员不能绕过职责隔离代做业务。
- 真实签署绑定记录版本、签署人、时间和含义并再认证；从系统时间源与校时策略获取时间，不能沿用原型固定日期。
- OOS/OOT/复测以关联记录保存，未经处置的异常阻断放行；不覆盖首次异常值。
- 放行后向ERP/WMS发送版本化事件，Outbox重试、幂等与回执闭环；禁止跨库直接更新。DMS更新先形成待审核版本，不改历史标准。
- 中文全文/模糊检索需用真实中文样例验证；不能把数据库默认英文全文配置视为满足URS-623。
- 仪器RS232/专有工作站使用受控边缘适配器，保留原始字节、校验、采集身份与解析版本；不假设纯浏览器能完成所有设备连接。

## 容量假设（未批准、未压测）

暂以300–800注册账号、100峰值在线、20–50持续业务操作用户建立第一轮负载模型；它不是实际测得并发。确定每天样品/检验项、附件大小、报表复杂度、仪器流量和5年以上数据增长后再决定资源。

可用应用4–8vCPU/16GB、数据库8vCPU/32GB与SSD作为隔离环境的起测配置建议，而非采购或容量保证；附件存储、备份、冗余和运维另算。压测必须保留URS-104原接受标准，不用p95或“任务已受理”偷换报表完成时间。

## 与HBOS、身份和AI的边界

HBOS可作为入口与经批准的身份集成方；LIMS有独立业务权限、数据和发布节奏。飞书/企业身份通过实际支持协议接入；首次开户不自动获得QC审批或全实验室数据权限。

AI可后置用于SOP检索、结果异常解释和资料辅助；不得直接改原始结果、代替签名或自动质量放行。AI故障不得阻断基础检验主流程；外部模型不得默认接收真实质量记录。
