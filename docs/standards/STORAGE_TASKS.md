# DATA-V1 文件存储、后台任务与一致恢复

## DATA-01 S3是接口，不是产品准入结论

文件与元数据分离的方向采用。PG保存object_id、业务对象/版本、storage_key、version_id、SHA-256、长度/MIME、来源、上传/采集者与时间、解析版本、保留分类和状态；原始字节保存在受控对象存储，不用文件名或ETag代替业务关联/完整性哈希。

**2026-11-16核查：官方minio/minio仓库标明于2026-04-25归档并只读；因此不将社区MinIO设为新LIMS的无条件生产默认。** 这不等于认定同名商业服务全部停运。商业支持版本或其他维护中的S3兼容产品，需分别核查生命周期、补丁、许可、私有部署、支持协议和实际功能；本轮未采购、未选定替代供应商。标准S3适配器可先用合成fake实现合同测试；不能把fake/开发环境结果当目标生产存储验证。

生产存储准入为阻断门禁：实际产品/版本、许可及支持、TLS/身份、对象版本与禁止覆盖、按风险批准的Object Lock/WORM或可验证等效控制、保留/法律保留、权限拒绝、可读性、备份与恢复、退出导出均需有证据。S3兼容不意味着支持全部Object Lock语义；WORM也不等于法规符合证明。禁止在UI未确认保留期时启动不可逆锁定或自动删除。

## DATA-02 上传、归档和下载

对象存储不参加PG事务。采用staged→verified→available/finalized状态；上传后计算/核对哈希、扫描、确认来源再建立可用关联。失败文件隔离/清理策略有期限和审计，未完成文件不得进入批准报告。每次重传使用新对象key/版本，禁止覆盖已被签署引用的版本。

提供授权后端下载或短时签名URL；URL泄露/过期/用户撤权窗口必须评估，高敏感附件可经API代理校验。bucket不得public，浏览器不得获取管理凭据。报告生成使用被批准的数据快照与模板版本，生成失败有状态，不能先发布空报告再补内容。归档内容和签署依据不同步时阻断发布。

## DATA-03 Celery与Redis

首版选择Celery，不并列实施ARQ；ARQ官方README处于maintenance-only，新增长期质量系统不优先采用。Celery部署为独立worker进程，默认同步任务；不得把async API函数直接作为会被自动await的任务。长任务须超时/取消/重试边界与失败可见。

PG事务写业务记录和Outbox；dispatcher发布已提交事件；消费者根据业务唯一键去重，记录状态/尝试/错误。消息可能重复、延迟或丢失，Celery确认配置不自动提供exactly-once。任务持久台账和对账器在PG中，能够补投未完成事件；worker中途被杀、broker重启/满容量、重复投递、回执丢失都要测试。

Redis缓存/短期会话与任务broker至少使用隔离实例/资源和凭据，不能认为不同DB编号就隔离了淘汰、持久化或故障。broker设置经验证的持久化、容量告警和不淘汰策略；缓存可重建，broker不可当业务权威库。会话依赖失败要安全拒绝/按批准方案恢复，不能失联即免验。Redis许可证按固定版本评估。

Redis broker visibility timeout、ETA、ack/retry需针对实际最长任务测试；稳定性多年时间点等远期计划保存在PG，由调度器定时投递到期任务，不把几个月后的任务长期塞进broker。重建缓存/清空队列不得改变受控样品或签名事实。

## DATA-04 一致恢复

备份涵盖PG、对象版本、报告、审计、必要配置和恢复密钥；备份副本与生产故障域隔离，加密和访问受控。PG时间点恢复必须与仍可获取的对象版本相匹配，清点孤立/缺失对象。恢复后验证哈希、数量、标准版本、签名/报告关联和时间顺序，恢复Outbox时不得重复外发放行。

保留期、RPO、RTO由QA/IT根据影响批准，本轮不填虚构承诺。Docker volume不是备份，成功备份不等于成功恢复。真实目标环境的恢复演练和完整性核对完成前，不得关闭验证门禁。
