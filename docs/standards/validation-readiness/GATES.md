# 开发阶段与质量门槛

本文件把“现在能开始什么”和“何时必须拿出证据”分开。G0–G5 是本增补的关口标识，不替换旧路线图 S0–S5，也不改变原 URS 对 DQ、FAT、IQ/OQ/PQ 等交付的约定。开发、风险分析和证据从第一版开始，正式执行在固定候选上进行。

| 关口 | 放行对象 | 进入下一步所需内容 | 决定者 |
| --- | --- | --- | --- |
| G0 规范与仓库基线 | 规范/治理 PR | 源件完整；新增规则可读；治理反例被拒；实际非作者审阅；必需检查及服务端保护落实 | Owner/维护者和非作者评审者；质量解释由相应 QC/QA 审核 |
| G1 领域设计确认 | 某一受影响领域的 FS/DS、模型和接受标准 | 用途/风险/范围清楚；该领域关键歧义和参数有受控决定；URS/子需求可追踪 | QC/QA、IT 与研发按职责 |
| G2 纵向功能完成 | 合成环境的可演示完整功能 | 契约、迁移、页面、API、权限、原值、审计、版本及必要签名一起交付；有正常/拒绝/边界/并发/故障测试 | 非作者工程评审；QC 参与业务演示 |
| G3 正式验证候选 | 固定制品和目标环境 | 固定提交/制品digest/配置/迁移/模板；产品及供应商准入；受控证据库；预先批准协议/预期；可用的安装/运行安排 | QA/IT/验证负责人 |
| G4 正式质量使用 | 批准范围内的质量试点/上线 | 适用 IQ/OQ/PQ 或有批准依据的等效证据、偏差处置、恢复/迁移、SOP/培训、主本切换、VSR、QA 对用途/版本/环境/限制的批准 | 授权 QA 和业务 Owner |
| G5 持续有效 | 在用系统的维护/扩展/退役 | 权限/审计复核、事件、补丁/变更影响、必要再验证、恢复演练、保留及退役可读 | 系统 Owner、QA、IT |

G1 未关闭某个质量语义，不阻止无关模块、合成数据、布局或安全基础设施准备。它阻止的是在未批准假设上冻结该领域质量规则或实施正式质量动作。缩小试点范围不能删掉该试点用途必需的审计、权限、更正、异常和恢复控制。

## 五类状态

| 维度 | 示例初态 | 可以证明什么 | 不能推导什么 |
| --- | --- | --- | --- |
| 开发进度 | NOT_IMPLEMENTED | 是否已有实现 | 测试/验证/批准 |
| 工程测试 | NOT_RUN | 指定设计、用例、制品/配置下的实际工程结果 | 正式 OQ 或 QA 放行 |
| 验证执行 | NOT_RUN | 批准协议下的真实执行结论和偏差 | 独立复核或最终放行 |
| 独立复核 | NOT_REVIEWED | 指定范围已由合格非作者/相应质量角色审阅 | 无范围限制的系统合规 |
| 质量放行 | NOT_GRANTED | 授权 QA 对版本、环境、用途和限制的实际决定 | 新版本、新场景自动继承 |

[QUALITY_STATUS.json](../../templates/QUALITY_STATUS.json) 是未执行模板，不是已签署记录；生产状态应保存在企业受控系统。机器检查不可核验批准真实性时必须明确其边界。

## 第一条业务链的完成定义

以样品接收为例，同时交付样品号和生命周期约束、实验室范围、API 合同、数据库迁移、界面状态、原始记录、审计事务、并发/幂等处理、权限拒绝及证据。后续测试分配、结果录入、更正、审核、报告沿用同一公共能力。不能先做完整站点页面，再在末期集中补权限与审计。

建议 2–3 人分工：A 负责数据/领域/API 与迁移；B 负责前端/契约集成和交互测试；第三人若有则负责集成/故障测试/证据与交付。每个关键 PR 由另一名合格人员审阅。QC、QA、IT、验证服务商是另需投入的职责，不包含在 2–3 名开发人数中。

## 最小拒绝和恢复场景

| 测试族 | 必测的失败路径 | 对应 DEV |
| --- | --- | --- |
| 身份/授权/签署 | 越实验室、撤权、旧版签署、重放、违规同人复核 | 006–008、016 |
| 原始数据/事务 | 首次超限、更正、并发冲突、审计写失败、超时重试 | 009–011 |
| 方法/资源/OOS | 未批准版本、精度边界、资质过期、无调查采用合格复测 | 012–015 |
| 文件/报告/接口 | 半文件、错哈希、恶意模板、设备断线、重复事件、未知回执 | 017–020 |
| 时间/保留/恢复 | 时间漂移、到期/hold、恢复后对象不匹配、重复业务效果 | 021–024 |
| 发布/证据 | 依赖漂移、错版本证据、旧PASS遇新FAIL、无效范围决定 | 003–004、025–027 |

这些是候选测试要求，当前均不能标为已执行 OQ。接受标准在协议批准前具体化；历史失败和后续处置/复测同时保存。

## 参数与例外

参见 [DECISIONS.md](DECISIONS.md)。登录时限、签署时限、校时容差、RPO/RTO、保留期限、故障阈值等不得由 Agent 猜值。性能应保持 URS-103/104 的原要求，并另批准代表负载和计时边界；新增百分位指标不能偷偷替换旧要求。

小团队先实现一条带拒绝/恢复路径的闭环，阶段估算在复杂模板、设备接入和首条完整业务链后重估；本增补不新增工期承诺。
