# 自研 LIMS 生命周期与验证体系

**SDLC-CSV-V1｜2026-11-20｜PR #1 待审增补。** 本目录把 GAMP 5 第二版的方法转为 HB-Lims 的开发、测试、代码、配置和变更工作规则。它是已有 TECH-V1、FRAMEWORK-V1、28 条 DEV 约束的实施层，不另建一套技术栈，也不改变 V3.1 视觉风格。

## 三个共同约定

1. **要求充分，证据适度。** 按患者安全、产品质量、数据完整性及实际用途决定工作深度。配置复杂度、软件类别、业务风险分别判断；不按“自研”或“Cat 5”给所有依赖重复做完整验证。
2. **文件可以合并，内容和责任不能消失。** 同一领域的 FS、DS、CS 可以合在一份规格中；测试阶段可以在批准策略下组合或复用。原 URS-2108/2109 的交付约定仍须逐项追踪，裁剪必须记录理由并获相应批准。
3. **规划、执行、批准分别记录。** 本轮 SIA、风险和 VP 是有内容的项目草案；模板没有执行结果。GitHub PR、自动检查和 Agent 复核均不能代替企业 QA 的验证批准与质量使用决定。

## 与现有规范的关系

- 28 条 DEV：规定系统行为及工程控制目标。
- LC-001～LC-012：规定从需求到退役如何组织工作并证明控制有效。
- G0～G5：继续使用既有[阶段关口](../validation-readiness/GATES.md)，不新增并列关口。
- [工程证据契约](../../validation/ENGINEERING_EVIDENCE.md)：继续管理真实工程结果；本轮风险规划不向原 185 条 RTM 写入 PASS。
- [待决参数](../validation-readiness/DECISIONS.md)：仍是参数批准入口；本目录不私自补入密码时限、恢复指标、保留年限或签署规则。

## 本轮提取的范围

11 个上传文件全部登记；短篇法规/指南按完整条款及原页核对，长篇 GAMP/CSV 材料按目录覆盖与相关完整章节提取，关键表图视觉核对。扫描件、非官方译文、缺页及现行性差异均见来源评估。没有将扫描/OCR处理等同于逐页人工审计，也没有宣称穷尽所有药品、市场和现场专门法规。

公开仓库保留原创规范、最小来源定位、脱敏模板和规划。内部讨论稿、付费指南全文、用户原附件及真实验证记录不随本增补上传。
