# EVD-V1 验证证据与第三方协作（C13）

依据URS-2107/2108/2109及[REG-V1](REGULATORY_SCOPE.md)。Owner已认可本规划；QA批准和真实验证仍未完成。

## EVD-01 三种结论不能互换

工程测试通过：指定代码与环境下的测试结果。
验证用例通过：结果属于批准协议、适用工具/环境、固定版本、完整原始证据及偏差处置并经规定复核。
生产可用：QA完成总体评价、培训/SOP/基础设施及切换批准。

自动化测试可以成为候选证据，但不自动等于OQ；CI绿色、原型采用和厂商产品宣传都不等于验证完成。不得事后伪造预期结果、执行日期、签名或删除失败记录。

## EVD-02 一条功能的追踪链

URS原编号 → 功能表编号（适用时）→ C控制ID → 风险 → FS/DS及合同 → 实现PR/提交 → 测试用例 → 执行/原始输出 → 缺陷/偏差/复测 → 审阅/批准。

复杂URS拆多个子用例，但保留原条目；范围外/暂缓需要批准引用，不将未执行当不适用。使用[任务模板](../templates/TASK_BRIEF.md)、[证据模板](../templates/VALIDATION_EVIDENCE.json)和[发布清单](../templates/RELEASE_MANIFEST.json)。空模板不是已完成验证文件。

## EVD-03 固定候选与工具适用性

验证清单包含提交SHA、干净源码、构建与镜像digest、依赖/SBOM、迁移版本、环境/配置摘要、浏览器/字体/报告转换器、身份和测试数据版本。不得测试A制品后重新构建B制品而声称相同；Next构建期环境参数变化必须识别。

自动化工具和执行环境适用性由风险评估确定：测试断言可解释、失败能检出、数据/时间可追溯、证据输出完整。保存失败截图/日志/反例及重新运行记录；重试成功不覆盖第一次失败。第三方可以利用已审查研发证据，不必机械重复全部测试，但需有批准的利用理由和独立判断。

## EVD-04 服务分工

研发提交设计、受控源码、构建、开发测试及整改。第三方按合同提供验证策略/协议、执行或见证、偏差与总结；QA批准适用性、风险、协议和最终使用。厂家技术人员参与我方代码开发时，单独登记其开发角色；其代码的独立审阅/验证由非作者承担，不能以同一供应商名称掩盖自测自批。

正式文件按URS保持VMP/VP、深化URS、FS、DS、DQ、RA、FAT、IQ/OQ、PQ及适用执行记录、RTM、VSR、OM/MM和培训/运行资料的追踪。是否裁剪/等效利用须有批准依据，不能擅自减少URS约定。范围内关键偏差未关闭不得仅靠到期日期上线。

## EVD-05 保存与访问

公开GitHub只存脱敏测试定义、摘要、ID和受控证据引用，不存真实质量记录、个人签名、生产凭据或完整敏感证据。CI一天artifact仅为开发临时传输；正式证据按批准保存策略进入公司受控库，记录哈希、访问权限、归档时间和可读性。

发布门禁需实际确认企业批准者和时间；源码评审不等于质量放行。工程文档全部写齐仍不能把application_validation从NOT_RUN改为PASS。
