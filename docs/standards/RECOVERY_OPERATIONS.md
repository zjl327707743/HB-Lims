# OPS-V1 恢复、归档、运维与退役（C12/C14）

来源：URS-105/114/2001/2100–2109、独立LIMS要求和[法规矩阵](REGULATORY_SCOPE.md)。与[存储规范](STORAGE_TASKS.md)共同使用。

## OPS-01 保存与一致恢复（C12）

按记录类型批准保存期限、起算点、法律保留、可读性和销毁条件。URS的至少5年业务数据能力不是第5年自动删除许可。对象锁定/WORM按风险和实际产品能力批准，不在开发环境随意启用不可逆生产保留。

恢复范围包括PG业务/签名/质量审计/Outbox、对象版本、原始数据、报告、模板、必要配置、密钥及身份映射。pgBackRest/WAL可作为准入工具，但不自动保证与S3一致；恢复时按对象版本与哈希清点缺失/孤立文件，核对状态、数量、签名和时间顺序，防止恢复队列后重复发送放行。

在隔离环境执行恢复而非只看备份成功日志；记录恢复点、实际损失、持续时间及核对结果，对照QA/IT批准RPO/RTO。单机Compose的单点故障如不满足目标，应评估备用/冗余和停机流程，不用容器重启代替恢复。

## OPS-02 迁移、升级、退出

迁移前盘点数据与语义、附件、模板和签名关系，定义来源/目标映射及失败处理；迁移后核对数量、内容、精度、单位、状态、追溯关系及可读性。Alembic downgrade不能找回已删数据；采用预备份、扩展—切换—收缩和经测试的恢复或前向修复。

退役需可导出、可查询、保留原始数据及审计并明确读取软件/许可保障；源系统停用不等于删除依据消失。销毁须明确批准和记录。

## OPS-03 小团队权限与运行职责（C14）

研发可兼任工程工作，不得因此自批质量记录或代替QA批准。开发、迁移、运行、备份、验证账号最小权限分离；受控紧急提升有期限、原因、独立记录和事后复核，不能设置长期共享root或免认证后门。

发布构建一次、按digest推广；生产不绑定可变源码和latest镜像。任何生产变化有影响评估和必要回归/再验证，工程合并不自动上线。独立验证人员不得修改所验证基线后继续使用旧证据。

## OPS-04 最小运行清单

必须定义告警接收和处置：API错误、Outbox/任务积压、采集失联/缓冲满、备份陈旧、空间不足、证书/凭据将过期、校时漂移、权限变更和审计复核逾期。质量审计、安全事件和运维遥测分开保存及审阅，不以统一日志平台替代质量审计。

建立账号授予/撤销、审计审阅、故障/事件、补丁、备份恢复、周期评估、变更及退出SOP。周期由风险批准，不把本文件中的开发节奏当法定频次。

试点前证明：隔离恢复、拒绝越权、受控发布/应急访问、IdP故障、仪器中断及回退流程实际可用。未演练不能因有手册就标PASS。
