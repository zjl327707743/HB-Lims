# LES-V1 配置、计算、资源、异常与时间链（C04/C05/C06/C07/C11）

来源：URS-500/600–624/703/704/706/900–903/1000–1210/1306/1508/1600–1807及功能表5/7/9–13/19–21/24/26–27。具体适用与业务参数由QC/QA批准；原编号不重排。

## LES-01 受控配置（C04）

标准、方法、公式、流程、模板、限度及动态字段采用草稿→复核→批准→生效→停用的受控版本。流程定义限定状态、动作、角色、签署含义、前置条件、退回/撤回/跳过规则；不开放任意Python/JS/SQL执行。配置变化也是质量变化，进行影响评估与必要回归。

执行创建时绑定获准版本/快照；新配置生效不追溯改写旧执行。变更旧执行依据需显式迁移/修订决定，不通过后台直接改外键。最低版本机制从第一条业务链就实现；完整模板设计器可后续扩展，但不能先产生无版本记录。

## LES-02 计量、公式与统计（C05）

区分原始值、单位、计算值、修约值、报出值和判定，保留算法/参数版本。采用Decimal/numeric及受控十进制接口，不把JS浮点显示值当权威。

QC确认有效数字与小数位、四舍五入/四舍六入五留双、分步与最终修约、科学计数、单位换算、稀释倍数、空值/未测/ND/<LOD/<LOQ和边界比较；没有方法依据不默认转换为0或默认合格。

建立固定金标准样例及独立计算对照；性质测试补充负值、边界、极值和顺序不变量。保存失败反例。图表仅呈现后端统计结果，控制限/趋势规则需版本和来源，不能由图表库现场生成质量结论。

## LES-03 步骤和资源准入（C06）

每个适用步骤引用执行者资格、方法/SOP、仪器有效校准和状态、试剂/标准品/溶液批次与效期；涉微生物时包含培养基和菌种传代。保存当时检查结果及资源版本，关键动作前再检查有效性，不能只在登录时检查一次。

试点只需所用资源的最小受控台账、校验和流水，不必先做完整维修/备件系统。培养基/菌种若是试点方法必需，就不得延期其必要控制。TMS/DMS可外置，但失联、新鲜度超限、撤销资格或未批准文档版本必须按QA批准策略拒绝或进入受控例外，不能默认放行。

并发扣减用数据库约束/事务防超扣；管制品两名不同有效身份；设备状态从可用变成失效时，尚未完成操作须重新判断。禁止复制各域自己的权限或签名实现。

## LES-04 OOS/OOT与QMS（C07）

保留功能表第5项模式一（LIMS完整OOS/OOT/AR）的选择，第6项模式二为0。第21项QMS接口也保留。设计前须明确调查、偏差、CAPA、失效判定和最终结案的唯一主记录及责任，使用稳定事件ID和回执，不让两边各有一个最终状态。

第一次异常、重测、重采样、调查结论及采用理由形成关系。复测合格不能自动抹去第一次异常；结果选择或失效须有批准依据。OOT/AR和状态含义待QC/QA明确。第一期异常范围可以小，但足以处理试点实际异常，未支持复杂情况应阻断并进入经批准的受控处理，不假装全功能。

LIMS检验报告批准与QA整批产品放行分开命令、角色及事件。向WMS发送的含义须在合同中明确，不因结果合格自动解锁全部质量处置。

## LES-05 稳定性/留样/EM时间链（C11）

计划条件、时间点、允许窗口、区域/点位状态和数量版本化；0月结果引用保留来源。计划变更不移动历史采样时间点。实际取样、交接、培养、暴露、计数和异常发生时间与系统接收时间区分，使用受控时区/校时。

长期计划保存在PG，调度器投递到期任务；重启、补投、重复通知不产生重复样品。漏采、超窗、数量不一致须可见并进入处置，不能后补时间掩盖。留样销毁与数据销毁是不同批准过程。

## LES-06 进入试点前的证据

配置换版历史不变；未批准配置拒绝；旧版本签署拒绝；金标准及边界计算；人员/校准/耗材过期；同人双签；并发超领；OOS调查/采用依据；跨系统结案冲突；计划换版与漏采恢复。全部有前后状态、固定版本和实际回执；没有执行的一律NOT_RUN。

法规定位与版本见[REG-V1](REGULATORY_SCOPE.md)，本文件的状态机/表结构/用例设计属于项目实现选择，不冒称法规唯一技术实现。
